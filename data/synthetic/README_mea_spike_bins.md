# MEA binned spike table schema

## Purpose

This dataset is an analysis-ready CSV for an interactive MEA spike-train visual analytics platform.
It is designed to be easy for collaborators to upload without reformatting, while still keeping names and units explicit.

The file is **not raw MEA voltage data**. It is a binned spike feature table: each row is one electrode in one time bin in one trial.
For raw voltage or long-term archival neurophysiology data, formats such as NWB are more appropriate. For human EEG/iEEG/MEG datasets, BIDS-style organization is often used. This CSV is the practical interchange layer used after spike detection/binning.

## Files

- `mea_spike_bins_standard.csv`: a versioned synthetic input file for the demo platform.
- `README_mea_spike_bins.md`: this schema and usage note.

## Table shape

- Recording: `rec_001`
- Electrodes: 64 electrodes arranged as an 8 x 8 MEA grid
- Conditions: `baseline`, `training`, `post`
- Trials: 18 total, 6 per condition
- Trial duration: 30 seconds
- Bin size: 0.5 seconds
- Rows: 69,120

## Required columns

| Column | Type | Unit | Meaning |
|---|---:|---:|---|
| `recording_id` | string | none | Recording/session identifier. Use the same value for all rows from one recording. |
| `trial_id` | string | none | Trial identifier, e.g. `trial_001`. |
| `condition` | string | none | Experimental state. This synthetic demo uses `baseline`, `training`, and `post`. |
| `bin_start_s` | number | seconds | Start time of the analysis bin relative to trial onset. |
| `bin_end_s` | number | seconds | End time of the analysis bin relative to trial onset. |
| `electrode_id` | string | none | Stable electrode/channel identifier, e.g. `E001`. |
| `x_um` | number | micrometers | Electrode x coordinate on the MEA plane. |
| `y_um` | number | micrometers | Electrode y coordinate on the MEA plane. |
| `spike_count` | integer | spikes/bin | Number of detected spikes in this electrode and time bin. |
| `firing_rate_hz` | number | Hz | Spike count divided by bin duration. The platform can recompute it from `spike_count`, `bin_start_s`, and `bin_end_s` if needed. |

## Why this schema is intentionally small

Earlier versions included fields such as `electrode_region`, `electrode_role`, `quality_flag`, `network_burst_flag`, and distance-to-center values. Those are useful for analysis, but they are not ideal as user-required input columns because they force collaborators to adopt project-specific annotations.

This version keeps only the columns that most users can provide or derive easily:

1. identity columns: `recording_id`, `trial_id`, `condition`, `electrode_id`;
2. time-bin columns: `bin_start_s`, `bin_end_s`;
3. electrode geometry: `x_um`, `y_um`;
4. spike features: `spike_count`, `firing_rate_hz`.

All summaries such as `summary_by_electrode.csv`, `summary_by_condition.csv`, connectivity matrices, burst flags, and network metrics should be generated by the platform after upload.

## Minimum acceptable user input

For maximum convenience, the platform should accept this exact single CSV.
If a user does not have `firing_rate_hz`, the platform should compute:

```text
firing_rate_hz = spike_count / (bin_end_s - bin_start_s)
```

If a user keeps electrode coordinates in a separate channel map, the platform can later support an optional `electrodes.csv`, but it should not be required for the first demo.

## Example rows

```csv
recording_id,trial_id,condition,bin_start_s,bin_end_s,electrode_id,x_um,y_um,spike_count,firing_rate_hz
rec_001,trial_001,baseline,0.000,0.500,E001,0,0,1,2.000
rec_001,trial_001,baseline,0.000,0.500,E002,200,0,0,0.000
```

## Suggested platform behavior

After upload, the platform should automatically produce these derived tables internally:

- `summary_by_electrode`: mean firing rate, total spikes, active-bin ratio, condition differences;
- `summary_by_condition`: condition-level mean and variance;
- `connectivity_edges`: electrode-electrode functional connectivity computed from binned spike trains;
- `network_metrics`: average degree, clustering coefficient, modularity, efficiency, or other graph metrics.

Users should not be asked to prepare those tables manually.

## Notes for real datasets

If users start from raw MEA voltage recordings, the recommended workflow is:

1. detect spikes from raw voltage;
2. assign spikes to electrodes or sorted units;
3. choose a bin size, for example 50 ms, 100 ms, 500 ms, or 1 s;
4. count spikes by `trial_id × time_bin × electrode_id`;
5. export this CSV.

For this demo, the bin size is 0.5 seconds because it is convenient for visual analytics and keeps the file compact.
